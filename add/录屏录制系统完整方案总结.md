# 录屏录制系统完整方案总结
## 一、项目定位
Windows 平台高性能屏幕录制器，**优先保障音频稳定，视频可丢帧，声画自动同步**；采用多线程解耦架构，把采集、编码、音视频合并、转码分发拆成独立线程，切断背压跨链路传导，规避录屏软件最常见的音频卡顿、爆音、声画漂移、崩溃损坏录制文件问题。

## 二、整体技术链路
```
WASAPI事件驱动Loopback系统音频采集（HIGH线程）
        ↓
200ms SPSC小环形缓冲（保护WASAPI硬件回调，杜绝驱动超时丢音）
        ↓
HIGHEST优先级PCM搬运线程
        ↓
10s SPSC大环形缓冲（音频长时抖动兜底）
        ↓
ABOVE_NORMAL音频消费线程：PCM采样计数生成音频主时钟 → Audio PES包队列（bounded 200）

DXGI Desktop Duplication屏幕采集（NORMAL线程）
        ↓
BGRA原始帧队列（上限5帧，队列满丢弃旧帧保最新画面）
        ↓
BELOW_NORMAL视频编码线程：SIMD BGRA→I420 + OpenH264 H.264编码 → Video PES包队列（bounded 60）

Mux线程（独立时序合并）
    非阻塞拉取音视频PES包，本地双VecDeque预缓存
    以音频为权威主时钟，视频PTS滞后>120ms自动丢弃过期视频包
    按时序择优输出TS包，周期性插入PAT/PMT表
    写入FFmpeg标准输入管道

FFmpeg子进程（BELOW_NORMAL进程优先级）
    输入：MPEG-TS流
    视频：直接copy H.264码流，不二次编码
    音频：子进程内部完成AAC编码
    输出：fmp4分片MP4（empty_moov+dash+faststart，崩溃断电不损坏已录制分片）

全局：异步日志模块，所有日志脱离音视频关键线程，独立线程IO输出，消除println隐形阻塞
```

## 三、核心架构设计与收益
### 音频链路（最高优先级，核心优化点）
1. **两层SPSC环形缓冲**：硬件回调只做内存写入，全部业务逻辑剥离到搬运线程，解决WASAPI录屏最致命的回调超时丢音。
2. **音频时钟为主时钟**：PTS由音频采样计数生成，作为整个系统唯一权威时间基准，避免视频时间戳累积漂移。
3. **AAC编码卸载到FFmpeg子进程**，音频业务线程仅做内存拷贝，CPU开销极低。
4. 全音频链路`try_send`非阻塞，音频PES队列满策略：丢弃旧音频包保留最新实时音频，防止背压反向阻塞音频采集。

### 视频链路（可牺牲帧，保障同步）
1. DXGI采集瞬间打QPC时间戳，编码耗时不污染帧PTS。
2. 原始BGRA帧队列严格限制5帧上限，编码跟不上时自动丢弃积压旧帧，画面持续追赶音频时钟。
3. OpenH264编码线程降低优先级，不会抢占音频线程CPU时间片。
4. Mux层内置视频滞后检测，视频包落后音频超过120ms直接丢弃，防止声画偏移持续累积。

### Mux多路合并层
1. 音视频PES完全独立生产队列，**音视频生产互相隔离**，视频卡顿/堆积不会影响音频链路。
2. Mux线程仅负责时序排序、TS打包、管道写入；pipe阻塞只会卡住mux线程，音视频采集、编码继续运行，包堆积在PES队列缓冲。
3. 周期性输出PAT/PMT，保证TS流容错，FFmpeg持续可解析。

### FFmpeg子进程
1. 进程优先级调低，避免FFmpeg内部编码抢占系统CPU资源。
2. fmp4分片输出，分片间隔2秒，程序意外退出时，前面已经完成分片可以正常播放。

### 全局稳定性优化
1. 线程优先级分层：WASAPI回调>HIGHEST搬运线程>音频消费>采集>视频编码，利用操作系统调度器优先保障音频。
2. 异步日志：日志不占用音视频关键路径，消除IO阻塞隐患。
3. COM对象遵循线程隔离规则：WASAPI、DXGI COM对象各自在线程内创建释放，不跨线程传递。

## 四、当前系统瓶颈与边界（客观限制）
1. **唯一单点阻塞源：FFmpeg stdin pipe write_all**。内核pipe缓冲区有限，FFmpeg读取持续阻塞会卡住mux线程；缓冲上限合计约12秒，如果FFmpeg持续阻塞超过该时长，最终会丢失音频包。
2. TS流内LPCM音频码率较高（48k立体声f32≈3Mbps），会增加pipe带宽压力；如果出现管道压力过高，备选方案：Rust侧输出AAC PES包替代LPCM。
3. DXGI仅支持主显示器捕获；锁屏、分辨率变更、显示器插拔会导致DXGI捕获会话中断，需要额外增加捕获会话自动重启逻辑（可选扩展）。
4. Windows不建议使用REALTIME线程优先级，存在整机卡死风险，本方案未使用。

## 五、已完成交付模块清单
1. audio_capture.rs：两层SPSC环形缓冲 WASAPI音频接收
2. audio_consumer.rs：音频消费、PTS生成、音频PES入队
3. wasapi.rs：事件驱动WASAPI loopback采集
4. dxgi_capture.rs：DXGI桌面复制BGRA屏幕捕获、CapturedVideoFrame定义
5. video_util.rs：SIMD BGRA转I420颜色转换
6. video_consumer.rs：OpenH264编码、视频PES入队
7. mux.rs：TS时序合并、PAT/PMT生成、PES打包写入pipe
8. ffmpeg_proc.rs：FFmpeg进程启动，设置进程优先级
9. logger.rs：异步全局日志模块
10. common.rs：全局常量、MediaPacket、AudioClock、QpcTimer、线程/进程优先级工具
11. main.rs：完整系统启动组装入口

## 六、可选扩展（非必需，按需后续迭代）
1. Ctrl+C信号捕获，全链路优雅退出、资源释放、关闭管道
2. DXGI捕获会话异常自动重建（锁屏/显示器插拔重试）
3. 多显示器采集支持
4. 替换LPCM为AAC PES，降低TS码率，减轻pipe压力
5. 内存池复用PCM、YUV、PES缓冲区，减少堆内存分配
6. 音频PES crossbeam-channel替换为无锁SPSC ring，多核重度负载进一步降低锁竞争

## 七、方案结论
该方案已经完成**架构层面全部高收益优化**。系统核心目标「优先保音频、自动声画同步、抗CPU抖动、崩溃保留已录片段」全部落地；现存问题均为物理边界限制，不再有架构级优化空间，剩余仅为工程稳定性扩展，不改变核心录制能力。

## 二、保留项及原因

| 目录/文件 | 原因 |
|---|---|
| `ffmpeg-n9.0-latest-win64-lgpl-shared-9.0/` | `FFMPEG_DIR`：头文件/导入库/运行 DLL/CLI，构建与回归必需 |
| `_llvm/bin/libclang.dll` | `ffmpeg-sys-next` bindgen 需要；删了无法从源码重建 |
| `ffmpeg-min/` | 发布包 5 个精简 FFmpeg DLL 的来源；`dist`/`manual-test` 依赖 |
| `native/yuv.lib` | `build.rs` 静态链接 libyuv（`ARGBToI420`） |
| `native/openh264.dll` | `build.rs` 复制为 `openh264.dll` + `openh264-7.dll` |
| `native/crt_stubs.c` | `build.rs` 编译 CRT 链接桩 |
| `native/bindgen-stubs/cuda_stub.h` | bindgen 的 CUDA 头文件桩 |
| `add/`、`legacy/` | 历史参考实现（约 143 KB）；不参与编译，但 `DESIGN.md` / `工作日志` 仍有引用 |
| `_rust/smoke/` | e2e 测试的兜底素材（`*.plain.mp4`），约 0.7 MB |
| `dist/`、`manual-test/` | 发布/手动验证包；已刷新到当前 release |
| `BUG_REPORT.md`、`WORK_SUMMARY_*.md`、`工作日志.md`、`docs/` | 历史/设计记录，不是运行期垃圾 |

## 四、顺手修掉的一个脚本回归

`scripts/dev-sign.ps1` 在之前的 UTF-8 编辑中丢失了 BOM，导致 **Windows PowerShell 5.1**
把中文注释按 ANSI 解析、脚本直接语法报错。已重新写回 **UTF-8 with BOM**，签名实测通过。

## 五、重建方式

```powershell
cd D:\deepseek-harness\default-workspace\CapLite
.\_build-env-san.bat build --release --bin CapLite
# 产物：target\release\CapLite.exe（未签名；target 会重新生成）
```

如果只想验证源码、不想再留 5 GB 构建缓存，可把 `CARGO_TARGET_DIR` 指到项目外，
验证完删除该临时目录。

## 六、还能进一步清理的（需要你确认）

1. `dist/` + `manual-test/` 共约 59 MB：如果不再需要发布/手动验证包，可以整目录删除；
   源码和 `ffmpeg-min` 仍在，随时能重建。
2. `add/` + `legacy/`：历史参考，约 143 KB；`DESIGN.md` / `工作日志` 有引用，
   删了会让文档出现悬空引用，所以这次保留。
3. `ffmpeg-n9/bin/ffmpeg.exe`/`ffprobe.exe`/`ffplay.exe`：约 168 MB；
   `regression.ps1` 会真调 `ffmpeg`/`ffprobe`，不建议删。若只做最小构建，
   可以另建一个只含 `include/lib/5 个 DLL` 的 `FFMPEG_DIR`，但会改变回归脚本的前置条件。
